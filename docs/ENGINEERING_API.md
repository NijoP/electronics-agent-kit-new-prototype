# EAK Engineering API (harness tool reference)

Implemented by `crates/eak-harness` (ADR-0018). Agent workflow and context rules:
[`AGENT_HARNESS.md`](AGENT_HARNESS.md). The authoritative, always-current list with JSON input
schemas is `eak tools --json` (or MCP `tools/list`).

## Transport

* **CLI** `eak` — `--json` prints exactly one envelope; subcommands `tools`, `guide`, `new`,
  `info`, `call`, `exec`, `check`, `history`, `export`, `mcp`.
* **MCP** — `eak mcp` / `eak-mcp`: JSON-RPC 2.0 over stdio (`initialize`, `tools/list`,
  `tools/call`, `ping`). `tools/call` returns the envelope as text and `structuredContent`;
  `isError` mirrors `ok == false`.
* **App endpoint** — while the desktop app has a project open it serves the same tools on a local
  socket (Unix domain socket in a 0700 directory on Linux/macOS; 127.0.0.1 TCP on Windows) with a
  random token in a user-only file, and advertises it in `<project>/.harness.json` (endpoint,
  token-file path, pid, project id; never the token). Request/response: one JSON line each,
  `{"token","tool","args","context"}` → envelope. The CLI and MCP use it automatically.

## Envelope

```json
{"ok": true, "tool": "PlaceSymbol", "category": "design", "route": "direct",
 "project": {"id": "prj_…", "name": "…", "dir": "/abs/folder", "revision": 4},
 "session": {"id": "s-1", "agent": "claude-code"},
 "result": { … }}
```
On failure `"ok": false` and `"error": {"code", "message", "details"}`; `project` still echoes the
project's current id and revision when it was opened.

## Tools by category

**Read** (no effect): `project_info`, `list_symbols` (pins with absolute position and net),
`get_component`, `list_footprints` (pads with absolute position, size, drill, net), `get_board`
(outline, stackup, tracks, vias, zones, constraints), `get_connectivity` (copper groups, shorts,
ratsnest), `get_history` (journal revisions with actor, tool-call log, evidence files),
`get_design_summary`, `get_netlist`, `list_library_components`, `classify_domain`, and the
calculators `calc_trace_width`, `calc_conductor_clearance`, `calc_led_resistor`,
`calc_voltage_divider`, `calc_linear_regulator`, `calc_rc_time_constant`.

**Design** (one revision per call; `expected_revision` required): one tool per
`eak_runtime::Command` variant (44, generated by `eak-intelligence` from the command set, so
schema and serde shape cannot drift), plus `Undo` and `Redo`. Each tool's `class` is its approval
class; the session approves up to `engineering_impacting` unless the user opted into
`destructive`. Results are the engine's `CommandResponse` (`op_id`, `revision_before`,
`revision_after`, `created`, `affected`, `warnings`) plus `rerun_checks`.

**Simulation** (no effect): `simulation_status`, `run_simulation` (ngspice; refused with
`simulator_unavailable` when not installed).

**Validation** (stores evidence): `run_check` with `erc`, `drc`, `mech`, `dfm` or `all`. Each
report: `check`, `revision`, `input_sha256`, `outcome`, `errors`, `warnings`, `findings[]`
(`id`, `rule_id`, `severity`, `message`, `objects`, `location`, `measured`, `required`,
`suggested_fix`), `not_implemented`, `limitations`, `rules_evaluated`, `evidence_path`.

**Manufacturing** (writes `output/rev-N/`): `export_manufacturing` (optional
`expected_revision`); re-runs every check, stores evidence, returns the manifest (gates,
blocking reasons, files with hashes). A package with failing gates is a draft.

**Project / discovery**: `create_project`, `list_tools`, `guide`.

## Provenance

* Design changes are journaled (`journal.jsonl`) with actor `agent:<name>@<session>`.
* Every harness call is appended to `<project>/harness-calls.jsonl` (time, session, agent, tool,
  ok/error code, revision, op id, check counts).
* Validation reports are stored as `evidence/<check>-rNNNNNN.json`.
All three are queryable with `get_history`.
