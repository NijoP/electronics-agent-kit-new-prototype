# ADR-0013: Simulation through an optional external ngspice

Date: 2026-11-14 · Source requirement: owner directive Part 11 ("Exaptation principle: borrow
capabilities, not code blindly"; ngspice and simulation integrations).

## Decision
Add `crates/eak-simulation`. It exports a SPICE netlist from the canonical EAK-IR schematic
connectivity (`eak_engineering::netlist`), runs the user's installed `ngspice -b` as a subprocess
with a timeout, parses the ASCII rawfile and returns typed `.op` / `.tran` results. Tauri IPC
(`simulation_status`, `run_simulation`) and a desktop Simulation panel sit on top.

## Context
A circuit solver is a large, solved problem. ngspice is installed (apt, version 42), runs on
Linux, macOS and Windows, and is BSD-3-Clause licensed (see `LICENSING.md`).

## Options considered
1. Write an in-tree MNA solver: months of work, a second source of numerical truth.
2. Link ngspice as a shared library (libngspice): tighter integration, but a native dependency
   for every build and platform, and a licence/packaging burden.
3. Subprocess the user's ngspice (chosen).

## Chosen option and rules
- ngspice is a **runtime, optional** dependency. Nothing else in EAK requires it; when it is
  missing every simulation entry point returns a clear "not installed" error with install hints
  (`EAK_NGSPICE` overrides the executable path). No ngspice code is copied or linked.
- Subprocess: `std::process::Command`, output redirected to files (no pipe deadlock), polled
  with a timeout and stopped with plain `Child::kill` (no process-group kills), scratch
  directory removed afterwards.
- Simulation is **read-only**: it works on a clone of the current revision and is not a design
  mutation, so it does not go through `Engine::execute` and adds no `Command`.
- Mapping by library `refdes_prefix`: R, C, L (value must parse as an engineering value), D/LED
  (generic `EAK_D` / `EAK_LED` models, anode/cathode by pin name), V, I (whitelisted
  `DC`/`PULSE`/`SIN`/`PWL` specifications). Ground-named nets are node 0. Any other part is
  listed as skipped, never silently dropped. Extra per-run stimulus can be attached to nets
  (`ExtraSource`) without editing the design.
- Netlist-injection defence: source specs are character-whitelisted, node/refdes names are
  sanitised, the control block is generated by the runner only; no user text is a SPICE line.
- Results are labelled as computed by ngspice from generic models. They are not verification
  evidence: EAK does not self-certify, and `limitations` lists what is not modelled
  (manufacturer models, parasitics, tolerances, temperature, PCB effects).

## Consequences
- No IR change (no new field on `SymbolInstance`/`ComponentDef`), so no schema migration. Parts
  carry their value in `SymbolInstance.value`; per-part SPICE model references are future work.
- AC, DC sweep, noise and subcircuit/`.include` models are not implemented.
- Transient results are decimated to at most 2000 points for IPC.
